= 從基礎設施複雜度到模型即服務（Models-as-a-Service）

當基礎設施採自助服務模式，卻缺乏明確的治理原則或管控機制時，問題往往接踵而至：

- **資源申請困難：** 各團隊難以正確申請及規劃 GPU 資源規格
- **重複投入：** 多個團隊可能各自部署相同的模型
- **資源利用不佳：** 昂貴的 GPU 可能長期閒置或負載過重
- **支出缺乏控管：** 基礎設施成本持續攀升，卻缺乏明確的責任歸屬
- **焦點錯置：** 開發者需要的是模型存取能力，而非繁瑣的 GPU 管理工作

== 模型即服務：AI 大規模部署的更佳抽象層

為了克服上述挑戰，平台工程師必須建立一個集中式、安全且標準化的模型服務層，以達成以下目標：

**集中式模型管理**

* 部署與維護模型，並實施完善的生命週期管理
* 標準化版本控制、回滾與測試流程

**安全 API 閘道**

* 將所有模型存取導向具備身分驗證與流量限制的端點
* 提供涵蓋所有模型互動的完整可觀測性與監控

**對開發者友善的存取方式**

* 讓開發者無需管理底層硬體即可使用模型
* 協助各團隊專注於開發 AI 驅動的應用程式、代理及功能

**高效的資源利用**

* 集中並共享組織內的 GPU 資源
* 消除資源浪費，同時確保公平存取與成本控制
