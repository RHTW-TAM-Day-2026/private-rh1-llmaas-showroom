[#install-mcp]
= 安裝並驗證 RHEL MCP

在本模組中，您將在 Showroom 命名空間中部署個人專屬的 RHEL MCP Server。此伺服器透過 SSH 連線至您分配的 RHEL 10 Edge 主機，並且只能讀取以下應用程式日誌：

* `/var/log/kernel-cve-radar/access.log`
* `/var/log/kernel-cve-radar/error.log`
* `/var/log/kernel-cve-radar/auth-events.jsonl`

您分配的 Edge 主機為 `{edge_host}`，SSH 使用者為 `lab-user`，初始 SSH 密碼為 `{edge_password}`。

== 使用 Showroom 終端機

本模組中的所有指令，請從實驗指南右側顯示的終端機執行。

終端機在 Showroom Pod 內運行，使用的 ServiceAccount 只能管理您個人命名空間中的資源：

[source,console,role=execute,subs=attributes+]
----
oc whoami
oc projects
----

設定所有指令使用的命名空間：

[source,console,role=execute,subs=attributes+]
----
export MCP_NAMESPACE="showroom-{guid}-{user}"
export EDGE_HOST="{edge_host}"
----

驗證

[source,console,role=execute]
----
printf 'MCP_NAMESPACE=%s\nEDGE_HOST=%s\n' \
  "${MCP_NAMESPACE}" "${EDGE_HOST}"
----

[WARNING]
====
若 `EDGE_HOST` 顯示為 `edge.example.com`，請勿繼續操作；請舉手並通知工作坊管理員，他必須先執行 `cluster-init/lab-init.sh`，使 Showroom 接收到您分配的 `edge_host` 和 `edge_password`。

請勿執行 `oc new-project`，您的 ServiceAccount 無法建立專案。

請勿在 Showroom 終端機中依賴 `oc project`，其 kubeconfig 可能嘗試在 `/data` 下寫入，但該路徑不可寫入。以下所有指令均透過 `MCP_NAMESPACE` Shell 變數明確指定命名空間。
====

== 確認 Edge 應用程式日誌

連線至您分配的 RHEL 10 edge 主機，密碼為 `{edge_password}`：

[source,console,role=execute]
----
ssh \
  -o UserKnownHostsFile=/tmp/rhel-mcp-known-hosts \
  -o StrictHostKeyChecking=accept-new \
  lab-user@"${EDGE_HOST}"
----

確認作業系統/應用程式的日誌:

i.查看作業系統版本及發行版資訊

[source,console,role=execute]
----
cat /etc/redhat-release
----

ii. 列出日誌目錄的詳細資訊

[source,console,role=execute]
----
ls -l /var/log/kernel-cve-radar/
----

iii.針對目前使用者有權開啟並讀取的日誌文件，測試並輸出其內容

[source,console,role=execute]
----
for log in \
  /var/log/kernel-cve-radar/access.log \
  /var/log/kernel-cve-radar/error.log \
  /var/log/kernel-cve-radar/auth-events.jsonl
do
  test -r "${log}" && echo "READABLE ${log}"
done
----

預期存在的檔案為 `access.log`、`error.log` 和 `auth-events.jsonl`。

== 準備 Edge 主機的 SSH 授權目錄

後續的 RHEL MCP Server 會使用 SSH 金鑰登入 Edge 主機。執行 `ssh-copy-id` 前，必須先確認Edge 主機 `lab-user` 能夠寫入自己的 `~/.ssh/authorized_keys`。

目前仍在 Edge 主機上時，執行：

[source,console,role=execute]
----
LAB_USER=lab-user
LAB_HOME=$(getent passwd "${LAB_USER}" | cut -d: -f6)
LAB_GROUP=$(id -gn "${LAB_USER}")

sudo mkdir -p "${LAB_HOME}/.ssh"
sudo touch "${LAB_HOME}/.ssh/authorized_keys"

sudo chown -R "${LAB_USER}:${LAB_GROUP}" ${LAB_HOME}/.ssh

sudo chmod 700 "${LAB_HOME}/.ssh"
sudo chmod 600 "${LAB_HOME}/.ssh/authorized_keys"

sudo restorecon -RF "${LAB_HOME}/.ssh"

stat -c "%U %a %n" "${LAB_HOME}/.ssh" "${LAB_HOME}/.ssh/authorized_keys"
----

確認擁有者為 `lab-user`，權限分別為：

[source,text]
----
lab-user 700 /home/lab-user/.ssh
lab-user 600 /home/lab-user/.ssh/authorized_keys
----

== 在 Showroom 終端機產生 MCP SSH 金鑰

Linux MCP Server 需要使用 SSH 金鑰連線至 Edge 主機。私鑰將建立於 Showroom 終端機，後續再存入 OpenShift Secret 並掛載至 RHEL MCP Pod；Edge 主機只需要接收對應的公鑰。

若目前仍連線在 Edge 主機，先返回 Showroom 終端機：

[source,console,role=execute]
----
exit
----

在 Showroom 終端機建立專用 SSH 金鑰。此實驗使用無密碼短語金鑰，讓 RHEL MCP 能以非互動方式連線：

[source,console,role=execute]
----
mkdir -p /home/lab-user/.ssh
chmod 700 /home/lab-user/.ssh

MCP_SSH_KEY=/home/lab-user/.ssh/id_ed25519.rhel_mcp_lab_user

if [ ! -f "${MCP_SSH_KEY}" ]; then
  ssh-keygen -q -t ed25519 -N '' \
    -f "${MCP_SSH_KEY}" \
    -C "rhel-mcp-lab-user@showroom"
fi

chmod 600 "${MCP_SSH_KEY}"
chmod 644 "${MCP_SSH_KEY}.pub"
----

將公鑰安裝至 Edge 主機的 `lab-user` 帳號，提示時輸入 `{edge_password}`：

[source,console,role=execute]
----
ssh-copy-id \
  -i "${MCP_SSH_KEY}.pub" \
  -o UserKnownHostsFile=/tmp/rhel-mcp-known-hosts \
  -o StrictHostKeyChecking=accept-new \
  lab-user@"${EDGE_HOST}"
----

[NOTE]
====
Showroom 終端機的 `/home/lab-user` 掛載自持久性儲存空間，但其 `$HOME` 可能指向 `/data`。請使用上方所示的明確 `/home/lab-user` 路徑和臨時 known-hosts 檔案。

私鑰應保留在 Showroom／MCP 端。
====

確認 RHEL MCP 專用金鑰可在不輸入密碼的情況下登入，並確認 `lab-user` 能讀取應用程式日誌：

[source,console,role=execute]
----
ssh \
  -i "${MCP_SSH_KEY}" \
  -o IdentitiesOnly=yes \
  -o BatchMode=yes \
  -o UserKnownHostsFile=/tmp/rhel-mcp-known-hosts \
  -o StrictHostKeyChecking=yes \
  lab-user@"${EDGE_HOST}" \
  'whoami; hostname; tail -n 2 /var/log/kernel-cve-radar/error.log'
----

您會看到指令的三項輸出


== 建立 SSH 金鑰 Secret

為了自動連線到 Edge 主機，RHEL MCP Pod 需要存取 SSH 私鑰。由於 Pod 無法直接讀取您終端上的文件，將金鑰保存為 OpenShift Secret 可以安全地將其傳遞給 Pod，從而使 Pod 能夠在無需密碼的情況下在後台進行登入。

[source,console,role=execute]
----
oc create secret generic rhel-mcp-ssh-key \
  -n "${MCP_NAMESPACE}" \
  --from-file=id_ed25519.rhel_mcp.key=/home/lab-user/.ssh/id_ed25519.rhel_mcp_lab_user \
  --dry-run=client -o yaml |
  oc apply -f -
----

== 建立 MCP 政策

MCP 策略透過明確將 RHEL MCP 伺服器的存取權限限制為僅限唯讀診斷作業（即 `read_log_file`、`get_journal_logs` 和 `get_service_status`），來執行最小權限原則。此策略將權限範圍限定在這些必要功能上，從而確保伺服器能夠從邊緣主機收集所需的遙測資料和健康狀態信息，同時透過防止未經授權的管理操作、系統修改或任意命令執行來降低安全風險。

[source,console,role=execute]
----
oc apply -f - <<EOF
apiVersion: v1
kind: ConfigMap
metadata:
  name: rhel-mcp-policy
  namespace: ${MCP_NAMESPACE}
data:
  mcp-policy.yaml: |
    rules:
      - host: "${EDGE_HOST}"
        tools: ["read_log_file", "get_journal_logs", "get_service_status"]
        all_users: true
        action: ssh_key
        ssh_key:
          path: /work/id_ed25519.rhel_mcp.key
          user: lab-user
EOF
----

== 部署 RHEL MCP Server

此步驟將 Linux MCP Server 及其內部叢集服務（連接埠 8000）部署到 OpenShift。此清單（manifest）使用初始化容器（init container）來設定所需的 SSH 金鑰權限（chmod 600），並利用 `rhel-mcp-policy` ConfigMap 強制執行伺服器存取控制。而`LINUX_MCP_ALLOWED_LOG_PATHS` 是一個明確的檔案白名單（各項之間以逗號分隔），它並不代表允許存取整個目錄樹。


[source,console,role=execute]
----
oc apply -f - <<EOF
apiVersion: apps/v1
kind: Deployment
metadata:
  name: rhel-mcp
  namespace: ${MCP_NAMESPACE}
spec:
  replicas: 1
  selector:
    matchLabels:
      app: rhel-mcp
  template:
    metadata:
      labels:
        app: rhel-mcp
    spec:
      initContainers:
        - name: prepare-ssh-key
          image: registry.redhat.io/ubi9-minimal:9.8-1786323074
          command: ["/bin/sh", "-c"]
          args:
            - >-
              cp /secret/id_ed25519.rhel_mcp.key
              /work/id_ed25519.rhel_mcp.key &&
              chmod 600 /work/id_ed25519.rhel_mcp.key
          volumeMounts:
            - name: ssh-key-secret
              mountPath: /secret
              readOnly: true
            - name: workdir
              mountPath: /work
      containers:
        - name: rhel-mcp
          image: quay.io/redhat-services-prod/rhel-lightspeed-tenant/linux-mcp-server:0.1.dev42
          imagePullPolicy: Always
          env:
            - name: LINUX_MCP_USER
              value: lab-user
            - name: LINUX_MCP_VERIFY_HOST_KEYS
              value: "False"
            - name: LINUX_MCP_ALLOWED_LOG_PATHS
              value: /var/log/kernel-cve-radar/access.log,/var/log/kernel-cve-radar/error.log,/var/log/kernel-cve-radar/auth-events.jsonl,/var/log/httpd/access_log,/var/log/httpd/error_log
          command: ["linux-mcp-server"]
          args:
            - --transport
            - streamable_http
            - --host
            - 0.0.0.0
            - --port
            - "8000"
            - --ssh-key-path
            - /work/id_ed25519.rhel_mcp.key
            - --user
            - lab-user
            - --policy-path
            - /config/mcp-policy.yaml
          ports:
            - name: http
              containerPort: 8000
          readinessProbe:
            tcpSocket:
              port: http
            initialDelaySeconds: 5
            periodSeconds: 10
          volumeMounts:
            - name: workdir
              mountPath: /work
            - name: policy
              mountPath: /config
              readOnly: true
      volumes:
        - name: ssh-key-secret
          secret:
            secretName: rhel-mcp-ssh-key
        - name: policy
          configMap:
            name: rhel-mcp-policy
        - name: workdir
          emptyDir: {}
---
apiVersion: v1
kind: Service
metadata:
  name: rhel-mcp
  namespace: ${MCP_NAMESPACE}
spec:
  selector:
    app: rhel-mcp
  ports:
    - name: http
      port: 8000
      targetPort: http
data:
  config: |
    Host *
        ServerAliveInterval 30
        ServerAliveCountMax 3
        TCPKeepAlive yes
        ConnectTimeout 15
        BatchMode yes
        IdentitiesOnly yes
EOF
----

等待伺服器就緒：

oc get pods,service \

== 測試 MCP 工具

透過在 Pod 內執行 Python 腳本來測試 MCP 伺服器功能，該腳本使用 fastmcp 用戶端連接到 `127.0.0.1:8000/mcp`。此操作將執行完整的協定握手，並針對所有已授權的日誌路徑呼叫 `read_log_file` 工具，從而驗證伺服器能否透過 SSH 向 Edge 主機進行驗證並取得日誌。

[source,console,role=execute]
----
oc exec -i \
  -n "${MCP_NAMESPACE}" \
  deployment/rhel-mcp -- \
  env EDGE_HOST="${EDGE_HOST}" \
  /opt/venvs/mcp/bin/python - <<'PY'
import asyncio
import os
from fastmcp import Client

HOST = os.environ["EDGE_HOST"]
LOGS = [
    "/var/log/kernel-cve-radar/access.log",
    "/var/log/kernel-cve-radar/error.log",
    "/var/log/kernel-cve-radar/auth-events.jsonl",
]

async def main():
    async with Client("http://127.0.0.1:8000/mcp") as client:
        for log_path in LOGS:
            result = await client.call_tool(
                "read_log_file",
                {
                    "host": HOST,
                    "log_path": log_path,
                    "lines": 3,
                },
            )
            print(f"=== {log_path} ===")
            print(result.content[0].text)

asyncio.run(main())
PY
----

三個呼叫均須成功回傳日誌內容。

image::en@modules:ROOT:rhel-mcp-tool-log-results.png[RHEL MCP read_log_file results for the allowed application logs,width=90%]

== 執行否定測試

透過嘗試存取 `/var/log/messages`（該路徑未包含在 `LINUX_MCP_ALLOWED_LOG_PATHS` 中）來驗證安全執行情況。執行此 Pod 內的 Python 測試可確認 MCP 伺服器確實按預期拒絕了針對未獲準日誌檔案的請求

[source,console,role=execute]
----
oc exec -i \
  -n "${MCP_NAMESPACE}" \
  deployment/rhel-mcp -- \
  env EDGE_HOST="${EDGE_HOST}" \
  /opt/venvs/mcp/bin/python - <<'PY'
import asyncio
import os
from fastmcp import Client

async def main():
    async with Client("http://127.0.0.1:8000/mcp") as client:
        try:
            await client.call_tool(
                "read_log_file",
                {
                    "host": os.environ["EDGE_HOST"],
                    "log_path": "/var/log/messages",
                    "lines": 3,
                },
            )
        except Exception as exc:
            print(exc)

asyncio.run(main())
PY
----

== 疑難排解

=== SSH 無法在 `/data` 下寫入

使用明確路徑和可寫入的 known-hosts 檔案：

[source,console,role=execute]
----
-o UserKnownHostsFile=/tmp/rhel-mcp-known-hosts
----

=== `oc project` 回報 `mkdir /data: permission denied`

保持 `MCP_NAMESPACE` 已設定，並在每個 `oc` 指令中以 `-n` 傳入。不需要切換專案。

=== MCP 回報 `SSH connection closed`

重新啟動部署以清除過期的 MCP 或 SSH 工作階段：

[source,console,role=execute]
----
oc rollout restart deployment/rhel-mcp \
  -n "${MCP_NAMESPACE}"

oc rollout status deployment/rhel-mcp \
  -n "${MCP_NAMESPACE}" \
  --timeout=5m
----

=== 查看伺服器日誌

[source,console,role=execute]
----
oc logs \
  -n "${MCP_NAMESPACE}" \
  deployment/rhel-mcp \
  --tail=100
----
