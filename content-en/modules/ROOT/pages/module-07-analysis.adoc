= Analyze the Edge Application Logs

== Configure RHEL MCP in Cline

When Cline runs in OpenShift Dev Spaces, configure it with your personal
cluster-internal RHEL MCP Service URL.

. Open Cline and select *MCP*.
+
image::cline-select-mcp.png[Cline MCP button,width=80%]

. Select *Remote Servers*.
+
image::select-remote-server.png[Cline MCP remote server,width=60%]

. Enter these values:
+
[cols="1,2"]
|===
|Field |Value

|Server Name
|`rhel-mcp`

|Server URL
|`http://rhel-mcp.showroom-{guid}-{user}.svc.cluster.local:8000/mcp`

|Transport Type
|`streamableHttp`
|===
+
image::cline-mcp-server-settings.png[Cline MCP Server settings,width=80%]

. Click *Add Server*.
+
image::click-add-server.png[Cline Add MCP Server,width=80%]

. Select *Configure*.
+
image::cline-mcp-configure-button.png[Cline MCP Configure button,width=80%]

. Select *Configure MCP Servers*. The `cline_mcp_settings.json` file opens in
the editor on the right.
+
image::select-configure-mcp-servers.png[Cline MCP settings JSON file,width=80%]

. Expand *rhel-mcp*, then select *Auto-approve* for the `read_log_file` tool.
+
image::enable-read-log-file-tool.png[Auto-approve the read_log_file tool,width=80%]

. Confirm the generated configuration:
+
[source,json,role=execute,subs=attributes+]
----
{
  "mcpServers": {
    "rhel-mcp": {
      "url": "http://rhel-mcp.showroom-{guid}-{user}.svc.cluster.local:8000/mcp",
      "type": "streamableHttp",
      "disabled": false,
      "autoApprove": [
        "read_log_file"
      ]
    }
  }
}
----
+

. After confirming that the settings are correct, click *Done* to return to the
Cline chat panel.
+
image::click-done-mcp-setting.png[Done button in Cline MCP settings,width=80%]

If Cline was already running, reload the Dev Spaces window or restart the Cline
session after saving the MCP configuration.

== Analyze the Three Application Logs

Use the exact MCP tool name and argument names. `read_log_file` requires
`log_path`, not `path`.

Examine the three application logs using the exact MCP tool name and arguments. Note that `read_log_file` requires the `log_path parameter`, not `path`.

Paste this prompt into Cline:

[source,text,role=execute,subs=attributes+]
----
Use the MCP tool rhel-mcp__read_log_file to read these files from
{edge_host}:

1. /var/log/kernel-cve-radar/access.log
2. /var/log/kernel-cve-radar/error.log
3. /var/log/kernel-cve-radar/auth-events.jsonl

For every tool call, use:
{
  "host": "{edge_host}",
  "log_path": "<one of the paths above>",
  "lines": 200
}

Do not use read_file.
Do not use local file reading.
Do not guess another host or path.

Correlate the timestamps, user, source IP, request IDs, role changes, denied
requests, successful administrative access, CVE findings, and data export.
Return a concise incident timeline, severity, impact, and recommended actions.
----

image::cline-rhl-mcp-prompt.png[Cline RHEL MCP prompt,width=80%]

The response should identify the important sequence across all three logs,
including the unauthorized privilege change and the subsequent sensitive
report export.

image::cline-rhel-mcp-response.png[Cline RHEL MCP response,width=80%]

== Test the Log Allowlist

Paste this prompt into Cline:

[source,text,role=execute,subs=attributes+]
----
Call exactly this MCP tool and arguments:

Tool: rhel-mcp__read_log_file
Arguments:
{
  "host": "{edge_host}",
  "log_path": "/var/log/messages",
  "lines": 20
}

Do not use another tool or path.
----

The request must fail because `/var/log/messages` is not one of the three
allowed application logs.

image::cline-rhel-mcp-allowlist-failure.png[Cline RHEL MCP allowlist failure,width=80%]

== Troubleshooting

We found that Cline uses *Local File Reading* and *path Instead of log_path* so let us modify the above prompt with the correct tool and arguments. We configure Cline to read local files by explicitly targeting the rhel-mcp__read_log_file tool (using its configured MCP server key rather than the RHOAI display name RHEL-MCP-Server).

[source,text,role=execute,subs=attributes+]
----
Call exactly this MCP tool and arguments:

Tool: rhel-mcp__read_log_file
Arguments:
{
  "host": "{edge_host}",
  "log_path": "/var/log/kernel-cve-radar/error.log",
  "lines": 200
}

Do not use another tool or path.
----


=== The MCP Connection Works but SSH Closes

Wehn MCP Connection wroks but SSH closed, restart your personal MCP deployment from the Showroom terminal:

[source,console,role=execute,subs=attributes+]
----
oc rollout restart deployment/rhel-mcp \
  -n showroom-{guid}-{user}

oc rollout status deployment/rhel-mcp \
  -n showroom-{guid}-{user} \
  --timeout=5m
----
