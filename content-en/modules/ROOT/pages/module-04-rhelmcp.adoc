= Install and Validate RHEL MCP

In this module, you will deploy a personal RHEL MCP Server in your Showroom namespace. The server connects to your assigned RHEL 10 Edge host over SSH and can read only the following application logs:

* `/var/log/kernel-cve-radar/access.log`
* `/var/log/kernel-cve-radar/error.log`
* `/var/log/kernel-cve-radar/auth-events.jsonl`

Your assigned Edge host is `{edge_host}`, the SSH user is `lab-user`, and the initial SSH password is `{edge_password}`.

== Use the Showroom Terminal

Run all commands in this module from the terminal displayed on the right side of the lab guide.

The terminal runs in the Showroom Pod with a ServiceAccount that can manage resources only in your personal namespace:

[source,console,role=execute,subs=attributes+]
----
oc whoami
oc projects
----

Set the namespace used by all commands:

[source,console,role=execute,subs=attributes+]
----
export MCP_NAMESPACE="showroom-{guid}-{user}"
export EDGE_HOST="{edge_host}"
----

Validate:

[source,console,role=execute]
----
printf 'MCP_NAMESPACE=%s\nEDGE_HOST=%s\n' \
  "${MCP_NAMESPACE}" "${EDGE_HOST}"
----

[WARNING]
====
If `EDGE_HOST` shows `edge.example.com`, stop and inform the workshop administrator — he/she must run `cluster-init/lab-init.sh` first to generate your assigned host and password.

Do not run `oc new-project`. Your ServiceAccount cannot create projects.

Do not rely on `oc project` in the Showroom terminal. Its kubeconfig may attempt to write under `/data`, which is not writable. All commands below explicitly specify the namespace through the `MCP_NAMESPACE` shell variable.
====

== Access the Application Logs on Edge Host

Connect to your assigned RHEL 10 edge host with password `{edge_password}`:

[source,console,role=execute]
----
ssh \
  -o UserKnownHostsFile=/tmp/rhel-mcp-known-hosts \
  -o StrictHostKeyChecking=accept-new \
  lab-user@"${EDGE_HOST}"
----

Access the operating system/application logs

Identify the OS version and distribution:

[source,console,role=execute]
----
cat /etc/redhat-release
----

Performs a detailed directory listing of the log folder:

[source,console,role=execute]
----
ls -l /var/log/kernel-cve-radar/
----

Tests and prints READABLE /path/to/file only for the logs the current user can successfully open and read:

[source,console,role=execute]
for log in \
  /var/log/kernel-cve-radar/access.log \
  /var/log/kernel-cve-radar/error.log \
  /var/log/kernel-cve-radar/auth-events.jsonl
do
  test -r "${log}" && echo "READABLE ${log}"
done
----

Expected output are READABLE for `access.log`, `error.log`, and `auth-events.jsonl`.

== Prepare the SSH Authorization Directory on the Edge Host

The RHEL MCP Server will later use an SSH key to log in to the Edge host. Before running `ssh-copy-id`, verify that `lab-user` on the Edge host can write to its own `~/.ssh/authorized_keys` file.

While you are still connected to the Edge host, run:

[source,console,role=execute]
----
LAB_USER=lab-user
LAB_HOME=$(getent passwd "${LAB_USER}" | cut -d: -f6)
LAB_GROUP=$(id -gn "${LAB_USER}")

sudo mkdir -p "${LAB_HOME}/.ssh"
sudo touch "${LAB_HOME}/.ssh/authorized_keys"

sudo chown -R "${LAB_USER}:${LAB_GROUP}" ${LAB_HOME}/.ssh

sudo chmod 700 "${LAB_HOME}/.ssh"
sudo chmod 600 "${LAB_HOME}/.ssh/authorized_keys"

sudo restorecon -RF "${LAB_HOME}/.ssh"

stat -c "%U %a %n" "${LAB_HOME}/.ssh" "${LAB_HOME}/.ssh/authorized_keys"
----

Verify that the owner is `lab-user` and that the permissions are:

[source,text]
----
lab-user 700 /home/lab-user/.ssh
lab-user 600 /home/lab-user/.ssh/authorized_keys
----

== Generate the MCP SSH Key in the Showroom Terminal

To secure the Linux MCP Server with SSH key authentication, the keys are distributed as follows:

* Private Key: Generated in the Showroom terminal, saved in an OpenShift Secret, and mounted directly into the RHEL MCP Pod.

* Public Key: Installed solely on the Edge host.

If you are currently logged into the Edge host, please switch back to the Showroom terminal:


[source,console,role=execute]
----
exit
----

Generate a dedicated SSH key without a passphrase in the Showroom terminal to enable non-interactive connections for RHEL MCP:

[source,console,role=execute]
----
mkdir -p /home/lab-user/.ssh
chmod 700 /home/lab-user/.ssh

MCP_SSH_KEY=/home/lab-user/.ssh/id_ed25519.rhel_mcp_lab_user

if [ ! -f "${MCP_SSH_KEY}" ]; then
  ssh-keygen -q -t ed25519 -N '' \
    -f "${MCP_SSH_KEY}" \
    -C "rhel-mcp-lab-user@showroom"
fi

chmod 600 "${MCP_SSH_KEY}"
chmod 644 "${MCP_SSH_KEY}.pub"
----

Install the public key into the `lab-user` account on the Edge host using `{edge_password}` when prompted:

[source,console,role=execute]
----
ssh-copy-id \
  -i "${MCP_SSH_KEY}.pub" \
  -o UserKnownHostsFile=/tmp/rhel-mcp-known-hosts \
  -o StrictHostKeyChecking=accept-new \
  lab-user@"${EDGE_HOST}"
----

[NOTE]
====
The Showroom terminal has `/home/lab-user` mounted from persistent storage, but its `$HOME` may point to `/data`. Use the explicit `/home/lab-user` path and the temporary known-hosts file shown above.

Keep the private key on the Showroom/MCP side.
====

Verify that the dedicated RHEL MCP key can log in without a password and that `lab-user` can read the application logs:

[source,console,role=execute]
----
ssh \
  -i "${MCP_SSH_KEY}" \
  -o IdentitiesOnly=yes \
  -o BatchMode=yes \
  -o UserKnownHostsFile=/tmp/rhel-mcp-known-hosts \
  -o StrictHostKeyChecking=yes \
  lab-user@"${EDGE_HOST}" \
  'whoami; hostname; tail -n 2 /var/log/kernel-cve-radar/error.log'
----

You shall see the output of:

[source,text]
----
whoami
hostname
tail -n 2 /var/log/kernel-cve-radar/error.log 
----

== Create the SSH Key Secret

To connect to the Edge host automatically, the `RHEL MCP Pod` needs access to the `SSH private key`. Because the Pod cannot read files directly from your terminal, saving the key as an `OpenShift Secret` safely hands it over to the Pod so it can log in behind the scenes without requiring a password.


[source,console,role=execute]
----
oc create secret generic rhel-mcp-ssh-key \
  -n "${MCP_NAMESPACE}" \
  --from-file=id_ed25519.rhel_mcp.key=/home/lab-user/.ssh/id_ed25519.rhel_mcp_lab_user \
  --dry-run=client -o yaml |
  oc apply -f -
----

== Create the MCP Policy

The MCP Policy enforces the principle of least privilege by explicitly restricting the RHEL MCP server's access to read-only diagnostic operations: `read_log_file`, `get_journal_logs`, and `get_service_status`. By scoping permissions to only these essential functions, the policy ensures the server can collect required telemetry and health status from the Edge host while mitigating security risks by preventing unauthorized administrative actions, system modifications, or arbitrary command execution.

[source,console,role=execute]
----
oc apply -f - <<EOF
apiVersion: v1
kind: ConfigMap
metadata:
  name: rhel-mcp-policy
  namespace: ${MCP_NAMESPACE}
data:
  mcp-policy.yaml: |
    rules:
      - host: "${EDGE_HOST}"
        tools: ["read_log_file", "get_journal_logs", "get_service_status"]
        all_users: true
        action: ssh_key
        ssh_key:
          path: /work/id_ed25519.rhel_mcp.key
          user: lab-user
EOF
----

== Deploy the RHEL MCP Server

This step deploys the Linux MCP Server and its internal cluster Service (port 8000) to OpenShift. The manifest uses an init container to set required SSH key permissions (chmod 600) and enforces server access controls using the `rhel-mcp-policy ConfigMap`. Note that `LINUX_MCP_ALLOWED_LOG_PATHS` is an explicit, comma-separated file allowlist — it does not represent a recursively allowed directory.


[source,console,role=execute]
----
oc apply -f - <<EOF
apiVersion: apps/v1
kind: Deployment
metadata:
  name: rhel-mcp
  namespace: ${MCP_NAMESPACE}
spec:
  replicas: 1
  selector:
    matchLabels:
      app: rhel-mcp
  template:
    metadata:
      labels:
        app: rhel-mcp
    spec:
      initContainers:
        - name: prepare-ssh-key
          image: registry.redhat.io/ubi9-minimal:9.8-1786323074
          command: ["/bin/sh", "-c"]
          args:
            - >-
              cp /secret/id_ed25519.rhel_mcp.key
              /work/id_ed25519.rhel_mcp.key &&
              chmod 600 /work/id_ed25519.rhel_mcp.key
          volumeMounts:
            - name: ssh-key-secret
              mountPath: /secret
              readOnly: true
            - name: workdir
              mountPath: /work
      containers:
        - name: rhel-mcp
          image: quay.io/redhat-services-prod/rhel-lightspeed-tenant/linux-mcp-server:0.1.dev42
          imagePullPolicy: Always
          env:
            - name: LINUX_MCP_USER
              value: lab-user
            - name: LINUX_MCP_VERIFY_HOST_KEYS
              value: "False"
            - name: LINUX_MCP_ALLOWED_LOG_PATHS
              value: /var/log/kernel-cve-radar/access.log,/var/log/kernel-cve-radar/error.log,/var/log/kernel-cve-radar/auth-events.jsonl,/var/log/httpd/access_log,/var/log/httpd/error_log
          command: ["linux-mcp-server"]
          args:
            - --transport
            - streamable_http
            - --host
            - 0.0.0.0
            - --port
            - "8000"
            - --ssh-key-path
            - /work/id_ed25519.rhel_mcp.key
            - --user
            - lab-user
            - --policy-path
            - /config/mcp-policy.yaml
          ports:
            - name: http
              containerPort: 8000
          readinessProbe:
            tcpSocket:
              port: http
            initialDelaySeconds: 5
            periodSeconds: 10
          volumeMounts:
            - name: workdir
              mountPath: /work
            - name: policy
              mountPath: /config
              readOnly: true
      volumes:
        - name: ssh-key-secret
          secret:
            secretName: rhel-mcp-ssh-key
        - name: policy
          configMap:
            name: rhel-mcp-policy
        - name: workdir
          emptyDir: {}
---
apiVersion: v1
kind: Service
metadata:
  name: rhel-mcp
  namespace: ${MCP_NAMESPACE}
spec:
  selector:
    app: rhel-mcp
  ports:
    - name: http
      port: 8000
      targetPort: http
data:
  config: |
    Host *
        ServerAliveInterval 30
        ServerAliveCountMax 3
        TCPKeepAlive yes
        ConnectTimeout 15
        BatchMode yes
        IdentitiesOnly yes
EOF
----

Wait for the server to become ready:

[source,console,role=execute]
----
oc rollout status deployment/rhel-mcp \
  -n "${MCP_NAMESPACE}" \
  --timeout=5m

oc get pods,service \
  -n "${MCP_NAMESPACE}"

oc logs \
  -n "${MCP_NAMESPACE}" \
  deployment/rhel-mcp \
  --tail=50
----

== Verify the Service Endpoint

[source,console,role=execute]
----
MCP_URL="http://rhel-mcp.${MCP_NAMESPACE}.svc.cluster.local:8000/mcp"

curl -i -X POST "$MCP_URL" \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  --data '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize"
  }'

----

The request is expected to return `HTTP/1.1 200 OK` with a message requiring `content-type: text/event-stream`. This confirms that DNS and the Service are reachable; curl does not perform the MCP protocol handshake here.

== Test the MCP Tools

Test the MCP server functionality by running an in-pod Python script that uses the fastmcp client to connect to 127.0.0.1:8000/mcp. This performs a complete protocol handshake and calls the `read_log_file` tool against all authorized log paths, verifying that the server can authenticate to the Edge host via SSH and retrieve the logs:


[source,console,role=execute]
----
oc exec -i \
  -n "${MCP_NAMESPACE}" \
  deployment/rhel-mcp -- \
  env EDGE_HOST="${EDGE_HOST}" \
  /opt/venvs/mcp/bin/python - <<'PY'
import asyncio
import os
from fastmcp import Client

HOST = os.environ["EDGE_HOST"]
LOGS = [
    "/var/log/kernel-cve-radar/access.log",
    "/var/log/kernel-cve-radar/error.log",
    "/var/log/kernel-cve-radar/auth-events.jsonl",
]

async def main():
    async with Client("http://127.0.0.1:8000/mcp") as client:
        for log_path in LOGS:
            result = await client.call_tool(
                "read_log_file",
                {
                    "host": HOST,
                    "log_path": log_path,
                    "lines": 3,
                },
            )
            print(f"=== {log_path} ===")
            print(result.content[0].text)

asyncio.run(main())
PY
----

All three calls must successfully return log content.

image::en@modules:ROOT:rhel-mcp-tool-log-results.png[RHEL MCP read_log_file results for the allowed application logs,width=90%]

== Perform a Negative Test

Validate security enforcement by attempting to access `/var/log/messages`, which is not included in `LINUX_MCP_ALLOWED_LOG_PATHS`. Running this in-pod Python test verifies that the MCP server properly rejects requests for unapproved log files as expected:


[source,console,role=execute]
----
oc exec -i \
  -n "${MCP_NAMESPACE}" \
  deployment/rhel-mcp -- \
  env EDGE_HOST="${EDGE_HOST}" \
  /opt/venvs/mcp/bin/python - <<'PY'
import asyncio
import os
from fastmcp import Client

async def main():
    async with Client("http://127.0.0.1:8000/mcp") as client:
        try:
            await client.call_tool(
                "read_log_file",
                {
                    "host": os.environ["EDGE_HOST"],
                    "log_path": "/var/log/messages",
                    "lines": 3,
                },
            )
        except Exception as exc:
            print(exc)

asyncio.run(main())
PY
----

Expected result:

[listing]
....
Access to log file '/var/log/messages' is not allowed.
....

image::en@modules:ROOT:rhel-mcp-negative-allowlist.png[RHEL MCP blocking /var/log/messages because it is outside the log allowlist,width=90%]

== Troubleshooting

=== SSH Cannot Write Under `/data`

Use an explicit path and a writable known-hosts file:

[source,console,role=execute]
----
-o UserKnownHostsFile=/tmp/rhel-mcp-known-hosts
----

=== `oc project` Reports `mkdir /data: permission denied`

Keep `MCP_NAMESPACE` set and pass it with `-n` in every `oc` command. You do not need to switch projects.

=== MCP Reports `SSH connection closed`

Restart the deployment to clear stale MCP or SSH sessions:

[source,console,role=execute]
----
oc rollout restart deployment/rhel-mcp \
  -n "${MCP_NAMESPACE}"

oc rollout status deployment/rhel-mcp \
  -n "${MCP_NAMESPACE}" \
  --timeout=5m
----

=== View Server Logs

[source,console,role=execute]
----
oc logs \
  -n "${MCP_NAMESPACE}" \
  deployment/rhel-mcp \
  --tail=100
----
