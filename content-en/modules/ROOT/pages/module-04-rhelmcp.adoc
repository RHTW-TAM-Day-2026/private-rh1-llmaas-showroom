= Install and Validate RHEL MCP

In this module, you will deploy a personal RHEL MCP Server in your Showroom namespace. The server connects to your assigned RHEL 10 Edge host over SSH and can read only the following application logs:

* `/var/log/kernel-cve-radar/access.log`
* `/var/log/kernel-cve-radar/error.log`
* `/var/log/kernel-cve-radar/auth-events.jsonl`

Your assigned Edge host is `{edge_host}`, the SSH user is `lab-user`, and the initial SSH password is `{edge_password}`.

== Use the Showroom Terminal

Run all commands in this module from the terminal displayed on the right side of the lab guide.

The terminal runs in the Showroom Pod with a ServiceAccount that can manage resources only in your personal namespace:

[source,console,role=execute,subs=attributes+]
----
oc whoami
oc projects
----

Set the namespace used by all commands:

[source,console,role=execute,subs=attributes+]
----
export MCP_NAMESPACE="showroom-{guid}-{user}"
export EDGE_HOST="{edge_host}"
----

[source,console,role=execute]
----
printf 'MCP_NAMESPACE=%s\nEDGE_HOST=%s\n' \
  "${MCP_NAMESPACE}" "${EDGE_HOST}"
----

[WARNING]
====
Do not continue if `EDGE_HOST` displays `edge.example.com`. This is only the fallback value for local documentation builds. The workshop administrator must first run `cluster-init/lab-init.sh` so that Showroom receives your assigned `edge_host` and `edge_password`.
====

[IMPORTANT]
====
Do not run `oc new-project`. Your ServiceAccount cannot create projects.

Do not rely on `oc project` in the Showroom terminal. Its kubeconfig may attempt to write under `/data`, which is not writable. All commands below explicitly specify the namespace through the `MCP_NAMESPACE` shell variable.
====

== Verify the Edge Application Logs

Connect to your assigned RHEL 10 host. The password is `{edge_password}`:

[source,console,role=execute]
----
ssh \
  -o UserKnownHostsFile=/tmp/rhel-mcp-known-hosts \
  -o StrictHostKeyChecking=accept-new \
  lab-user@"${EDGE_HOST}"
----

Verify the operating system and application logs:

[source,console,role=execute]
----
cat /etc/redhat-release

ls -l /var/log/kernel-cve-radar/

for log in \
  /var/log/kernel-cve-radar/access.log \
  /var/log/kernel-cve-radar/error.log \
  /var/log/kernel-cve-radar/auth-events.jsonl
do
  test -r "${log}" && echo "READABLE ${log}"
done
----

The expected files are `access.log`, `error.log`, and `auth-events.jsonl`.

== Prepare the SSH Authorization Directory on the Edge Host

The RHEL MCP Server will later use an SSH key to log in to the Edge host. Before running `ssh-copy-id`, verify that `lab-user` on the Edge host can write to its own `~/.ssh/authorized_keys` file.

While you are still connected to the Edge host, run:

[source,console,role=execute]
----
LAB_USER=lab-user
LAB_HOME=$(getent passwd "${LAB_USER}" | cut -d: -f6)
LAB_GROUP=$(id -gn "${LAB_USER}")

sudo mkdir -p "${LAB_HOME}/.ssh"
sudo touch "${LAB_HOME}/.ssh/authorized_keys"

sudo chown -R "${LAB_USER}:${LAB_GROUP}" ${LAB_HOME}/.ssh

sudo chmod 700 "${LAB_HOME}/.ssh"
sudo chmod 600 "${LAB_HOME}/.ssh/authorized_keys"

sudo restorecon -RF "${LAB_HOME}/.ssh"

stat -c "%U %a %n" "${LAB_HOME}/.ssh" "${LAB_HOME}/.ssh/authorized_keys"
----

Verify that the owner is `lab-user` and that the permissions are:

[source,text]
----
lab-user 700 /home/lab-user/.ssh
lab-user 600 /home/lab-user/.ssh/authorized_keys
----

== Generate the MCP SSH Key in the Showroom Terminal

The Linux MCP Server requires an SSH key to connect to the Edge host. The private key will be created in the Showroom terminal, stored later in an OpenShift Secret, and mounted into the RHEL MCP Pod. The Edge host needs only the corresponding public key.

If you are still connected to the Edge host, return to the Showroom terminal:

[source,console,role=execute]
----
exit
----

Create a dedicated SSH key in the Showroom terminal. This lab uses a key without a passphrase so that RHEL MCP can connect non-interactively:

[source,console,role=execute]
----
mkdir -p /home/lab-user/.ssh
chmod 700 /home/lab-user/.ssh

MCP_SSH_KEY=/home/lab-user/.ssh/id_ed25519.rhel_mcp_lab_user

if [ ! -f "${MCP_SSH_KEY}" ]; then
  ssh-keygen -q -t ed25519 -N '' \
    -f "${MCP_SSH_KEY}" \
    -C "rhel-mcp-lab-user@showroom"
fi

chmod 600 "${MCP_SSH_KEY}"
chmod 644 "${MCP_SSH_KEY}.pub"
----

Install the public key in the `lab-user` account on the Edge host. Enter `{edge_password}` when prompted:

[source,console,role=execute]
----
ssh-copy-id \
  -i "${MCP_SSH_KEY}.pub" \
  -o UserKnownHostsFile=/tmp/rhel-mcp-known-hosts \
  -o StrictHostKeyChecking=accept-new \
  lab-user@"${EDGE_HOST}"
----

[NOTE]
====
The Showroom terminal has `/home/lab-user` mounted from persistent storage, but its `$HOME` may point to `/data`. Use the explicit `/home/lab-user` path and the temporary known-hosts file shown above.

Keep the private key on the Showroom/MCP side.
====

Verify that the dedicated RHEL MCP key can log in without a password and that `lab-user` can read the application logs:

[source,console,role=execute]
----
ssh \
  -i "${MCP_SSH_KEY}" \
  -o IdentitiesOnly=yes \
  -o BatchMode=yes \
  -o UserKnownHostsFile=/tmp/rhel-mcp-known-hosts \
  -o StrictHostKeyChecking=yes \
  lab-user@"${EDGE_HOST}" \
  'whoami; hostname; tail -n 2 /var/log/kernel-cve-radar/error.log'
----

== Create the SSH Key Secret

[source,console,role=execute]
----
oc create secret generic rhel-mcp-ssh-key \
  -n "${MCP_NAMESPACE}" \
  --from-file=id_ed25519.rhel_mcp.key=/home/lab-user/.ssh/id_ed25519.rhel_mcp_lab_user \
  --dry-run=client -o yaml |
  oc apply -f -
----

== Create the MCP Policy

This policy allows only `read_log_file`, `get_journal_logs`, and `get_service_status` calls to your assigned Edge host.

[source,console,role=execute]
----
oc apply -f - <<EOF
apiVersion: v1
kind: ConfigMap
metadata:
  name: rhel-mcp-policy
  namespace: ${MCP_NAMESPACE}
data:
  mcp-policy.yaml: |
    rules:
      - host: "${EDGE_HOST}"
        tools: ["read_log_file", "get_journal_logs", "get_service_status"]
        all_users: true
        action: ssh_key
        ssh_key:
          path: /work/id_ed25519.rhel_mcp.key
          user: lab-user
EOF
----

== Deploy the RHEL MCP Server

`LINUX_MCP_ALLOWED_LOG_PATHS` is an explicit, comma-separated file allowlist. It does not allow recursive access to the entire directory.

[source,console,role=execute]
----
oc apply -f - <<EOF
apiVersion: apps/v1
kind: Deployment
metadata:
  name: rhel-mcp
  namespace: ${MCP_NAMESPACE}
spec:
  replicas: 1
  selector:
    matchLabels:
      app: rhel-mcp
  template:
    metadata:
      labels:
        app: rhel-mcp
    spec:
      initContainers:
        - name: prepare-ssh-key
          image: registry.redhat.io/ubi9-minimal:9.8-1786323074
          command: ["/bin/sh", "-c"]
          args:
            - >-
              cp /secret/id_ed25519.rhel_mcp.key
              /work/id_ed25519.rhel_mcp.key &&
              chmod 600 /work/id_ed25519.rhel_mcp.key
          volumeMounts:
            - name: ssh-key-secret
              mountPath: /secret
              readOnly: true
            - name: workdir
              mountPath: /work
      containers:
        - name: rhel-mcp
          image: quay.io/redhat-services-prod/rhel-lightspeed-tenant/linux-mcp-server:0.1.dev42
          imagePullPolicy: Always
          env:
            - name: LINUX_MCP_USER
              value: lab-user
            - name: LINUX_MCP_VERIFY_HOST_KEYS
              value: "False"
            - name: LINUX_MCP_ALLOWED_LOG_PATHS
              value: /var/log/kernel-cve-radar/access.log,/var/log/kernel-cve-radar/error.log,/var/log/kernel-cve-radar/auth-events.jsonl,/var/log/httpd/access_log,/var/log/httpd/error_log
          command: ["linux-mcp-server"]
          args:
            - --transport
            - streamable_http
            - --host
            - 0.0.0.0
            - --port
            - "8000"
            - --ssh-key-path
            - /work/id_ed25519.rhel_mcp.key
            - --user
            - lab-user
            - --policy-path
            - /config/mcp-policy.yaml
          ports:
            - name: http
              containerPort: 8000
          readinessProbe:
            tcpSocket:
              port: http
            initialDelaySeconds: 5
            periodSeconds: 10
          volumeMounts:
            - name: workdir
              mountPath: /work
            - name: policy
              mountPath: /config
              readOnly: true
      volumes:
        - name: ssh-key-secret
          secret:
            secretName: rhel-mcp-ssh-key
        - name: policy
          configMap:
            name: rhel-mcp-policy
        - name: workdir
          emptyDir: {}
---
apiVersion: v1
kind: Service
metadata:
  name: rhel-mcp
  namespace: ${MCP_NAMESPACE}
spec:
  selector:
    app: rhel-mcp
  ports:
    - name: http
      port: 8000
      targetPort: http
data:
  config: |
    Host *
        ServerAliveInterval 30
        ServerAliveCountMax 3
        TCPKeepAlive yes
        ConnectTimeout 15
        BatchMode yes
        IdentitiesOnly yes
EOF
----

Wait for the server to become ready:

[source,console,role=execute]
----
oc rollout status deployment/rhel-mcp \
  -n "${MCP_NAMESPACE}" \
  --timeout=5m

oc get pods,service \
  -n "${MCP_NAMESPACE}"

oc logs \
  -n "${MCP_NAMESPACE}" \
  deployment/rhel-mcp \
  --tail=50
----

== Verify the Service Endpoint

[source,console,role=execute]
----
MCP_URL="http://rhel-mcp.${MCP_NAMESPACE}.svc.cluster.local:8000/mcp"

curl -i -X POST "$MCP_URL" \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  --data '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize"
  }'

----

The request is expected to return `HTTP/1.1 200 OK` with a message requiring `content-type: text/event-stream`. This confirms that DNS and the Service are reachable; curl does not perform the MCP protocol handshake here.

== Test the MCP Tools

Use the MCP Server's Python environment to call `read_log_file` through the MCP protocol:

[source,console,role=execute]
----
oc exec -i \
  -n "${MCP_NAMESPACE}" \
  deployment/rhel-mcp -- \
  env EDGE_HOST="${EDGE_HOST}" \
  /opt/venvs/mcp/bin/python - <<'PY'
import asyncio
import os
from fastmcp import Client

HOST = os.environ["EDGE_HOST"]
LOGS = [
    "/var/log/kernel-cve-radar/access.log",
    "/var/log/kernel-cve-radar/error.log",
    "/var/log/kernel-cve-radar/auth-events.jsonl",
]

async def main():
    async with Client("http://127.0.0.1:8000/mcp") as client:
        for log_path in LOGS:
            result = await client.call_tool(
                "read_log_file",
                {
                    "host": HOST,
                    "log_path": log_path,
                    "lines": 3,
                },
            )
            print(f"=== {log_path} ===")
            print(result.content[0].text)

asyncio.run(main())
PY
----

All three calls must successfully return log content.

image::en@modules:ROOT:rhel-mcp-tool-log-results.png[RHEL MCP read_log_file results for the allowed application logs,width=90%]

== Run a Negative Test

`/var/log/messages` is not in the allowlist:

[source,console,role=execute]
----
oc exec -i \
  -n "${MCP_NAMESPACE}" \
  deployment/rhel-mcp -- \
  env EDGE_HOST="${EDGE_HOST}" \
  /opt/venvs/mcp/bin/python - <<'PY'
import asyncio
import os
from fastmcp import Client

async def main():
    async with Client("http://127.0.0.1:8000/mcp") as client:
        try:
            await client.call_tool(
                "read_log_file",
                {
                    "host": os.environ["EDGE_HOST"],
                    "log_path": "/var/log/messages",
                    "lines": 3,
                },
            )
        except Exception as exc:
            print(exc)

asyncio.run(main())
PY
----

Expected result:

....

== Troubleshooting

=== SSH Cannot Write Under `/data`

Use an explicit path and a writable known-hosts file:

[source,console,role=execute]
----
-o UserKnownHostsFile=/tmp/rhel-mcp-known-hosts
----

=== `oc project` Reports `mkdir /data: permission denied`

Keep `MCP_NAMESPACE` set and pass it with `-n` in every `oc` command. You do not need to switch projects.

=== MCP Reports `SSH connection closed`

Restart the deployment to clear stale MCP or SSH sessions:

[source,console,role=execute]
----
oc rollout restart deployment/rhel-mcp \
  -n "${MCP_NAMESPACE}"

oc rollout status deployment/rhel-mcp \
  -n "${MCP_NAMESPACE}" \
  --timeout=5m
----

=== View Server Logs

[source,console,role=execute]
----
oc logs \
  -n "${MCP_NAMESPACE}" \
  deployment/rhel-mcp \
  --tail=100
----
