== The impact of AI code assistants

You're not just going to write code - you're going to collaborate with an **AI-powered teammate**.

Modern code assistants can:

* **Understand Full Project Context**: Assistants like Cline, GitHub Copilot, and Cursor can read across files and directories, understanding how your code fits together.

* **Edit code with Natural Language**: You can describe a change—like "add error handling here" or "convert this to async"—and AI-powered assistants can apply that change intelligently.

* **Proactively Suggest Improvements**: They catch bugs, highlight inefficiencies, and recommend best-practice patterns.

* **Automate Tedious Tasks**: From generating unit tests and docstrings to scaffolding boilerplate or renaming variables across a project—they take care of the grunt work so you can focus on logic and design.

These assistants don’t just write code - with the right guardrails and knowledge in place, they can understand your project and help you build better software faster. And the best part? Most of them work seamlessly inside popular IDE's like Visual Studio Code, so you don’t need to switch tools to get started.

== Step 1: Setting up a cloud integrated developer environment (IDE) with OpenShift Dev Spaces

As a developer, your environment should be fast, consistent, and ready to go for your work. That is what OpenShift Dev Spaces delivers: instant access to pre-configured, containerized workspaces — all running securely on your OpenShift cluster.

You could also leverage an exposed model API endpoint in your local environment as a developer, if the model is exposed properly. However, your company has not exposed the model outside of the confines of the cluster, so you are required to work within the environment and not locally.

== Step 2: Add Cline, Your Coding Teammate

**Cline** is an open-source AI coding agent that integrates into VS Code. It provides an interactive chat interface where you can describe a development task in natural language. With your approval, Cline can inspect files, propose and apply code changes, and run terminal commands. You can ask Cline to perform actions like:

**“Add logging to this function”**

**“Generate a unit test for this file”**

**“Refactor this into smaller components”**

**“Explain what this code does”**

Cline works directly in your editor with awareness of your codebase and project context. It shows proposed actions and changes so that you can review and approve them as you work.

What makes Cline particularly useful in this workshop is its support for OpenAI-compatible model endpoints. This allows you to connect the agent to the private model provided through Models as a Service (MaaS).

NOTE: Cline is the AI-powered coding agent used in this workshop. Similar workflows are possible with other coding assistants that support custom model endpoints.

== Step 3: Connect Cline to Your MaaS Model

Navigate to the **Cline sidebar icon** in the left-hand navigation panel.

image::cline-start-options-free.png[]

NOTE: If the Cline panel is too narrow, expand it by dragging its border.

We will do two things in this module:

. Connect to our MaaS model
. Use the model to help complete, review, and test a small manufacturing quality checker before moving into Edge log analysis.

To connect Cline to the MaaS model, you must provide the endpoint URL, API key, and model ID from the MaaS application.

NOTE: If needed, go back to the OpenShift AI dashboard to the AI asset endpoints section to retrieve the credentials.

=== Choose Bring Your Own Key

When Cline asks **How will you use Cline?**, select **Bring my own API key**.

This option is also known as **BYOK**, or **Bring Your Own Key**. It lets you connect Cline to the MaaS model endpoint and API token provided in this workshop instead of using Cline's hosted model options.

image::cline-byok-option.png[]

Click **Continue** to configure your provider.

=== Enter MaaS endpoint details

On the **Configure your provider** screen, set **API Provider** to **OpenAI Compatible**.

Enter the following values:

* **Base URL**: Enter your MaaS route and append `/v1`.
* **API Key**: Enter the API token generated from the MaaS interface.
* **Model ID**: Enter `qwen3-4b-instruct`.

For example:

* **Base URL**: `https://maas.apps.example.com/llm/qwen3-4b-instruct/v1`
* **API Key**: `your-actual-api-key-here`
* **Model ID**: `qwen3-4b-instruct`

IMPORTANT: Use the route copied from your own MaaS interface. Ensure that the Base URL ends in `/v1`, and do not share your API key.

image::cline-maas-provider-settings.png[]

Click **Continue** to save the provider configuration.

NOTE: If Cline shows an **Introducing Cline Kanban** prompt after saving the provider configuration, you do not need to install it for this workshop. Do not click **Run in terminal**. Close the prompt and continue.

image::cline-kanban-do-not-install.png[]

Reference the provider configuration documentation here: https://docs.cline.bot/provider-config/openai-compatible[Cline OpenAI-Compatible Provider Documentation]

When the model is properly configured, return to the Cline chat panel and confirm that `qwen3-4b-instruct` is the selected model.

Go ahead and send a short test message to confirm that the model responds.

image::cline-test-response.png[]

NOTE: If the Dev Spaces workspace is recreated or the Cline settings are reset, repeat the provider configuration with your MaaS endpoint and a valid API token.
